Verified B

One status, same words.

The client and the model see the same status name for the same booking, so a phone call or an email never has two vocabularies. Only the sentence and the next action differ. The chip is the existing rt-status shape from the account status badge, with booking colours.

The statuses

RequestedSent, waiting for the model. 48-hour window.
AcceptedConfirmed. Dates are blocked. Money has been taken.
CompletedThe shoot date has passed.
DeclinedThe model said no. Nothing charged.
ExpiredNot answered within the window. Nothing charged.
CancelledEnded after it was accepted. Money outcome stated alongside.

Red is not used: a model declining, or a request expiring, is a normal outcome, not an error. Amber is "waiting on someone", green is "confirmed", cobalt tint is "done", grey is "ended, nothing happening". The hollow dot on Expired is the only non-colour cue between the two grey chips, so the word always carries the meaning.

Design notes
  • One pattern for all statuses. A chip (the existing rt-status shape), a one-line title, a plain sentence, one next action. The same trio on the list row and on the page banner. The five asked-for statuses are Requested, Accepted, Declined, Expired and Completed; Cancelled is added because the process has it and a booking that was accepted can end that way.
  • Same names both sides. The old labels disagree: the list says "Requested" but the page says "Your booking request was successful!"; reviews say "Waiting for listing owner review". This replaces the owner/listing words with the model's name, drops the exclamation marks and removes "Inbox: As a customer / As a provider" in favour of "Your bookings" (client) and "Booking requests" (model).
  • Money is stated on every state that touches it. Requested: not charged. Accepted: charged. Declined and Expired: not charged. Cancelled: refunded or not. Completed (model): paid usually the next working day, always within five working days. No state leaves the client or model guessing.
  • Deadline in the list. A requested row shows the exact reply-by time (amber, bold). That is the one piece of urgency the model needs; no countdown animations, no "usually replies in" claims.
  • Colour. Amber = waiting, green = confirmed, cobalt tint = done, grey = ended. No red. Chips are read by label first and colour second; the hollow dot on Expired separates it from Declined for people who cannot rely on shade.
  • Tap targets and mobile. Each list row is at least 72px tall and fully tappable. Below 900px the matrix collapses to stacked rows with "Client sees" and "Model sees" labels. Nothing scrolls sideways.
  • Not designed here: filtering or sorting the lists (Upcoming and Past tabs would be the natural next step), and the cancel dialog (already exists, with refund shown before confirming).
