Design notes
  • Reordered for M6. The shoot comes first (what, when, where, location type), then the content licence, then payment last with the one cobalt action. The model has to be able to say yes to the shoot before money is a topic, and the client has already thought about the shoot when they arrive. On a phone the old flow ran to about 4.5 screens; this one is one scroll with a collapsed summary at the top (tap to expand the breakdown), numbered sections, and no repeat of the model's photo.
  • Dates are not asked again. They show as a read-only row with a "Change" link back to the profile, so the dates the client saw priced are the dates they are requesting.
  • Private residence. The location type is a radio list (not a dropdown) so "Private residence" is a visible, deliberate choice. Picking it shows a calm note to the client and the model is shown the existing safety note on their side (B08). The client is not told that some models decline residence shoots; if the model has switched that off, the request fails with the generic "not available" message at send time and the boundary is never revealed (SAF-13/14). The sole-trader restriction (SAF-06) is designed as a disabled option with a reason; it is not in the code today.
  • Licence. The five bullets are the plain-English box from the draft licence, shortened; the binding text is one tap away ("Read the full licence" opens it in a new tab). The checkbox label is the existing string. Final wording depends on the solicitor review, so the mock flags it as draft.
  • Payment, minimal and UK-sensible. Card details (Stripe's secure field), name on card (pre-filled), billing postcode and country (defaults to United Kingdom). The US/Finnish fields are gone: street address, "Apt #", city, "State" and the "Helsinki" and "00100" placeholders. We already hold the client's business address from onboarding. This changes what billing data is collected, so it is open question 4 rather than an assumption.
  • It is clear the card is not charged yet: in the subtitle, in a notice at the top of Payment, next to the total, and in the button's fine print area. The "temporary hold" sentence is standard card-authorisation behaviour; the Developer should confirm the wording against how the Stripe payment is set up.
  • "What happens next" sits beside the form on desktop and inside the collapsed summary on phones. The third line (free to cancel until 48 hours before the shoot) is the two-tier cancellation policy; it must match the published Terms before launch (open question 8).
  • Mobile. Inputs are 48px, radio rows 52px, tick rows 44px, Change link 44px. The card field is one line that scales; at 375px "Card number / MM / YY / CVC" fit without wrapping. Nothing scrolls sideways.
  • Single cobalt action: "Send booking request". The numbered circles are ink, the Change link is ghost, and the licence link is an underlined link.
