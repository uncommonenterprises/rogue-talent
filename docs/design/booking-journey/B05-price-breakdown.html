Design notes
  • Arithmetic is on the surface. Day rate x days, then the 15% fee, then the total. Same rows in the panel, the phone sheet, checkout and the booking page, so a client never sees two different-looking prices for the same booking. The run-through example (2 days x £300 + 15% = £690) is what this shows for any rate.
  • "The model keeps 100%" is a plain sentence, not a footnote. The old copy used an asterisk and an em dash. The new line has neither and names the amount the model receives, which makes the wedge concrete without saying "no agency".
  • Honest about travel. If the model's travel costs setting is "Charged separately", the total is explicitly not the whole cost. The profile (B03) already says this; repeating it at the moment of payment avoids a surprise. If travel is included, the single line "Travel is included in the rate" sits in the note instead.
  • Model side. The model sees what they earn, not what the client pays, and that the fee is not taken from them. The payout timing line is the already-approved promise ("usually the next working day, always within five working days") and appears on the incoming request (B08) and after the shoot.
  • No taxes shown. The mock shows no VAT line because the product does not compute one. Whether prices need to show VAT is a compliance question already tracked in docs/compliance-open-items.md; this component can take an extra row if that changes.
  • Wording avoids gendered pronouns. Models have a gender field, but the system should not infer "she" or "he" from it. Copy uses the model's name, "the day rate" or "their".
