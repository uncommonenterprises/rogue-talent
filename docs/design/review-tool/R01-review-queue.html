What changes on a phone. The column header disappears. Each row stacks: name and city, then type, ID verification and the resubmission flag as chips, then the submitted date and how long ago.

Age colour. Anything waiting 3 days or more shows its age in amber. The profile page promises "usually within one working day", so the queue should make slow ones obvious. Threshold is a draft for Neil.

Cobalt. The only cobalt on this view is the active tab underline. Rows are links, not buttons.

Design notes
  • Built for "open it, tap the oldest, decide". Oldest first, no sorting controls, no search. With a queue this short, a filter box would be more to learn than to use. Tabs filter Models and Clients; "Recently decided" is the fourth tab so there is one place to look, not two pages.
  • Each row answers the four questions a reviewer asks before opening it: who, what kind, how long have they waited, and is Stripe already done. A reviewer can skip a not-yet-verified person if they want, but nothing is hidden.
  • ID verification is one chip per row. For models it is Verified only when both identity and bank are done; the split is on the review page. Green means done, amber in progress, grey not started. It is the existing rt-status set, no new colours.
  • Resubmission is an outlined tag on the row, with the previous decline shown inside the review page itself (R02).
  • Recently decided shows the last 7 days, newest first: decision, who decided, when, and where the email is ("Email due shortly" until the background job has run, then "Email sent 11:46"). Decline shows a neutral grey chip, not red (see R02 notes).
  • Team link in the nav only appears for admins. A reviewer who is not an admin sees "Review queue" alone.
  • Names, dates and cities are example data. No real people, no photographs: avatars are monograms.
