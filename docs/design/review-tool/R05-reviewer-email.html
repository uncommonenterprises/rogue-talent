What if
  • The person logs in but is not a reviewer: they see "You don't have access to this page" and nothing else (R07).
  • Someone else has already decided: they land on the review page showing that decision, with no buttons (R07).
  • The session runs out while they are deciding: the decision is not lost silently; they are asked to log in and come back to the same review (R07).
Design notes
  • Plain and short, as asked. A heading, one sentence, three facts (name, city, submitted date), one button, one line of explanation. No photos or profile text in the email: the reviewer sees those on the page, behind a log-in. An email can be forwarded or read on a lock screen, so it carries as little personal detail as possible.
  • The subject line carries the useful bit, in the exact form asked for ("New model profile to review: Imogen Hart"), with matching versions for a client and for a resubmission so a reviewer can triage from the inbox.
  • One cobalt button per email. The wordmark's cobalt full stop is the brand, not an action.
  • Everyone who reviews gets every email. First decision wins; anyone who opens the link afterwards sees the decision (R07). See open question 4.
  • Log-in is the standard page. The return-to-page behaviour is the one real build requirement here: after log-in the reviewer must land on the review page, not the default landing page. The Developer should check how the current post-log-in redirect behaves.
  • Email layout and sending should follow the existing Postmark templates; this page shows the content and hierarchy, not final HTML.
  • Names, dates and the address are example data.
