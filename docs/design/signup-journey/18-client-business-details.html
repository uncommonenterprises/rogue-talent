Design notes
  • The sign-up/step-2 split, and why: company name stays on the sign-up form (screen 03) because it's identity-defining and low-friction to type. Everything else moves here, after email verification, following the same progressive-disclosure principle as the model wizard: get the account created fast, ask for more once someone's committed.
  • Decided by Neil, 29/09: today's config (configUser.js) has company_registration_number set to displayInSignUp: true, i.e. it currently shows on the sign-up form. When this is built, the Developer will flip that to false and add this new step instead, a real config change, not just a visual one.
  • "Submit for approval" on this screen doubles as the client's Gate-A submission (there's no separate client "review" screen in this journey, unlike the model's 4-step wizard, since there's much less to review).
  • Revision 3 (Neil, 29/09) - Neil's feedback was that this screen "feels very light". It now opens with a required "Business type" choice (Limited company / Sole trader or self-employed), built with .rt-segmented (the approved DS segmented-control component, previously unused in the live product but already specified in DESIGN_SYSTEM.md §9). Sole traders - for example freelance photographers - are a planned client type per safety-framework-v1-scope.md's sole-trader rule, and have no Companies House number, so the form has to work for both without forcing a registration number that doesn't exist.
  • Revision 3 - Limited company (main card): Company name (pre-filled from sign-up, editable, hint "Check this matches your registered name"), Company registration number (required), Registered office address (required, full width, using the same Google Places autocomplete look as screen 08's city field), Business phone number (required, hint explains why it's asked and that it's never shown to models), Industry (optional, unchanged), Website (optional, unchanged).
  • Revision 3 - Sole trader (variant card below): no registration number field. Company name becomes "Business or trading name", with the hint "The name you trade under." Adds Business address (required, same address-autocomplete look) and "Website or social media link" (required - our main legitimacy signal for a sole trader, since there's no company number to check against). Business phone number is required the same as the limited-company card. Industry stays optional.
  • Revision 3 - Removed: VAT number (PM decision: not used anywhere in the product) and Typical project types (nothing reads or displays it). Both are deleted from this screen and will need deleting from the Console listing/user field config at build time.
  • Build notes for the Developer: new Console fields needed - business_type (enum: limited_company / sole_trader), business_address (one address field serves both paths: registered office address for limited companies, business address for sole traders; there is no existing address field for clients today), and a business phone field (currently the client's phone was collected at sign-up - this replaces that, scoped as private/business data, not shown on any public profile). company_registration_number becomes conditionally required (only when business_type = limited company). VAT number and Typical project types fields are removed in Console.
  • Mobile pass (29/09/2026): at 375px "Sole trader or self-employed" was wrapping onto two lines inside .rt-segmented's half-width segment, making each option ~61px tall and cramped. Below 480px the control now stacks as two full-width rows instead, so each option reads on one line with a comfortable tap target - fixed in journey.css, applies to both cards on this screen. 480px and above (including this screen's own two-column desktop layout) is unchanged.
