Design notes
  • Tone is respectful and specific, not a form-letter rejection. A reviewer note is quoted directly, framed as fixable rather than final. Red is used correctly here: this genuinely is a "danger/blocked" state, not decoration.
  • Open question (a build dependency, not just a design one): the quoted reviewer note assumes the operator can attach a short free-text reason when declining in Console/the approval tool. If that mechanism doesn't exist yet, this screen needs a fallback (e.g. a small fixed set of reasons) rather than a blank note. Flag to the Developer/PM before building this screen.
  • Open question: the screen list in the brief only specifies a model-side "Not approved" screen, with no client-parallel. Clients can also be declined at Gate A (failed Companies House check). Worth confirming whether that needs its own near-identical screen or can reuse this one's structure with client-specific copy.
  • "Contact us" is a ghost link, not a second competing primary. "Edit your profile" stays the one cobalt action, since resubmitting is the productive path for the vast majority of cases.
