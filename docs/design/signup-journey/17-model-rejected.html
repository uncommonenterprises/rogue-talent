Design notes
  • Tone is respectful and specific, not a form-letter rejection. A reviewer note is quoted directly, framed as fixable rather than final. Red is used correctly here: this genuinely is a "danger/blocked" state, not decoration.
  • Decided (PM, resolved): the decline reason is resolved. The operator enters a short reason in a private admin field in Sharetribe Console, and this screen reads and quotes it as the reviewer note. If no reason is entered, the screen shows a general fallback line instead of a blank note, for example: "We didn't include a specific note this time. If anything's unclear, contact us and we'll talk you through it."
  • Decided by Neil, 29/09: the client "Not approved" variant reuses this screen's layout with business wording rather than a separate design. It's shown below the model version as a second status card (state-label "Client variant").
  • "Contact us" is a ghost link, not a second competing primary, in both variants. Each card's primary action ("Edit your profile" / "Update your business details") stays the one cobalt action for that real screen; the two cards are shown stacked here only for review, never simultaneously in the live product.
